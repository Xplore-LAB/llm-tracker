POSITION 01

大模型应用算法工程师

字节跳动模型应用算法相关岗位 · 2027 届校招
ALGORITHM
5+
业务方向
方向 NLP 多模态 知识图谱 大模型训练与应用 后训练 RAG Agent 自演化 SFT/RL LLMs/VLMs/AIGC/Agent

▍招聘解读

大模型应用算法工程师岗位的考察，不只看论文、开源项目或竞赛经历，也会重点关注候选人在大模型训练、评测、效果优化和应用落地中的实际经验。

▍职位要求

  1. 2027 届统本科及以上学历，计算机、机器学习等相关专业优先
  2. 在 NLP 算法、多模态算法、大模型训练和应用、知识图谱等领域有实际的开发和实习经验者优先
  3. 思维开阔，具备优秀的逻辑思考能力，面对挑战性问题充满热情，具有良好的团队合作、沟通协调能力，执行力和自驱力强
  4. 学习能力强，对前沿技术持续关注，能够洞察技术和业务的结合点

▍求职 Tips

✦ 简历与投递建议
  1. 扎实的基本功必不可少，除具体项目外，面试官也可能会考察机器学习、深度学习、概率统计等基础概念
  2. 对研究背景方向并没有硬性限制，也欢迎上下游相关专业并对模型应用感兴趣的同学积极投递

▍面试真题测一测

Q1
简历中的这个项目/论文里，哪部分是你独立完成的？能否讲清楚从数据处理、模型训练、评测到上线（或实验结果）的全过程？
▶
◈ 考察点 这道题考察候选人对项目的真实思考。字节跳动的工作风格务实，期待候选人有比较扎实的项目基础，对项目细节——比如样本如何生成、脏数据如何处理、训练评测怎么做、过程中踩过哪些坑均有复盘和思考。
Q2
在这个项目中，SFT 和 RL 分别解决什么问题？有什么实验能够证明这两个阶段的必要性？
▶
◈ 考察点 这道题考察候选人对技术的理解。候选人对模型训练的理解非常重要，我们期待候选人对这些技术有比较深入的理解，并在自己的场景做过验证，而不只是跟风、为了做而做。
Q3
Pre-Norm 和 Post-Norm 有什么区别？项目用了哪个，为什么？
▶
◈ 考察点 这道题考察候选人的技术基础是否扎实。不只能够说清两者区别，更要讲清楚为什么 Pre-Norm 更稳定、为什么 Post-Norm 最终性能可能更好。当然，如果你还能进一步指出 Pre-Norm 稳定性背后的缺点，以及如何改进和业内开源模型的具体做法，那就更好啦。

POSITION 02

AI 全栈工程师

字节跳动 AI 相关研发岗位 · 2027 届校招
FULL-STACK
12+
业务方向
以下团队正在热招中 抖音研发 国际化商业产品技术 安全风控 中国广告交易 Tiktok 研发 剪映 CapCut 集团信息系统

▍招聘解读

AI 全栈工程师岗位的考察，不只看候选人对 AI 的理解，也会通过代码题、项目深挖或前置 AI 作业等，进一步考察候选人是否具备借助 AI 完成实际开发任务，并对 AI 生成结果进行判断验证和修改。

▍职位要求

  1. 2027 届统本科及以上学历，计算机、通信和电子信息科学、数字等相关专业
  2. 具备良好的计算机基础（数据结构、算法、计算机网络、操作系统等），并熟练使用至少一门编程语言
  3. 熟练使用 HTML5/CSS3/JavaScript/TypeScript/Vue/React 等前端技术，完成页面布局交互式开发，有全栈（GoLang）开发经验者优先
  4. 熟练使用 TRAE、Claude Code、Codex、Cursor 等任一 AI Coding 工具，练习过 Rules、MCP、Skills 并了解底层机制与基本原理者加分
  5. 认知 AI Coder 定位：明确自身长期发展规划，具备模块的学习能力和动手能力，能快速上手新领域技术，适配业务活动的开发模式
  6. 积极乐观，责任心强，具备良好的沟通协作能力，逻辑思维能力强以及服务意识

▍求职 Tips

✦ 简历与项目建议
  1. 简历里最好有一个完整项目，能讲清楚从前端交互、后端接口、模型接入到效果验证的全链路
  2. 表达尽量细致，如果你做过的项目涉及调用大模型 API，可以进一步说明你如何提升回答质量、降低延迟、控制成本和处理异常
  3. 如有相关经历，可以重点突出自己使用 AI 推动产品功能上线的项目，并复盘其中的技术选型、实际踩坑和后续优化方向

▍面试真题测一测

Q1
如果让你用 AI 工具完成一个真实业务需求，例如设计一个广告投放工具调用 Agent，你会如何理解项目、拆分需求，并设计前后端和模型调用链路？
▶
◈ 考察点 这道题考察候选人的端到端业务理解与工程落地能力。AI 全栈工程师不仅要写代码，还要懂业务和用户场景，拆解需求、设计架构，并善用 AI 工具提效。回答时建议更加全面，例如从业务流程、页面交互、前后端接口、Agent 决策逻辑、工具调用等环节整体说明。若能进一步说明各模块的职责边界、关键技术选型和完整的数据流转过程，会更加分。
Q2
如果要求你的 agent 的回复必须是符合 JSON Schema 的结构化内容，但用户反馈约 10% 的请求会出现"解析失败"或"字段缺失"，你如何把解析失败率降到 1% 以下？
▶
◈ 考察点 这道题考察候选人是否解决过实际工程中经常出现的边 case。建议同学可以先分析有可能的失败原因，再从以下角度作答：
  • 上下文与提示词优化
  • 工具调用策略改进
  • 二次模型校验
  • 切换更稳定的模型
  • 工程链路兜底（fallback 解析、规则补全）
Q3
Agent 运行过程中经常会遇到幻觉，你会如何排查这类问题？
▶
◈ 考察点 这道题考察候选人的知识广度。它是一个开放性问题，没有正确答案。大家可以结合自身优势，从模型输出、上下文拼接、Skill 召回等多个环节展开。

POSITION 03

AI Agent 开发工程师

字节跳动 · 2027 届校招
AGENT
★
校招重点

▍招聘解读

AI Agent 工程师岗位的考察，重点关注候选人对 Agent 运行机制和工程落地的理解，而不只是是否做过简单 Demo。部分团队会提前布置 Agent 相关作业，考察候选人能否在真实场景中完成需求拆解、技术选型、方案实现和问题排查。

▍职位要求

  1. 2027 届统本科及以上学历，计算机、软件工程等相关专业优先
  2. 开发语言和技术栈不限，熟悉 Golang/Python/TypeScript 优先，并熟悉常见的软件开发模式
  3. 对 AI 应用方向有强烈的兴趣，熟悉 Agent 相关的常见范式架构（如 Plan&Execute、ReAct、Workflow 等），熟悉模型的工作原理和特性，并能结合原理和特性做稳定化、成本和效果优化优先
  4. 业务理解能力强，能够针对业务上的需求梳理业务边界并快速匹配最合适的 Agent 工作流范式
  5. 对行业流行的常见模型优缺点有大致了解，并了解如何系统科学的评测帮助模型选型
  6. 掌握模型原理优先：对常见的 CNN、RNN、Transformer 模型结构及推理架构有一定的了解，对模型的二次训练原理及方法了解优先，如 SFT、LoRA-SFT、DPO 等

▍求职 Tips

✦ 项目与表达建议
  1. 简历里最好写一个完整 Agent 项目：任务目标是什么、接了哪些工具、如何处理失败、最终效果如何评估
  2. 面试中不要只讲框架名。更重要的是讲清楚你为什么这样拆任务，为什么需要这个工具，以及异常情况怎么处理
  3. 如果做过 RAG、自动化工作流、智能客服、代码助手、数据分析助手等项目，可以重点准备链路设计和效果评估

▍面试真题测一测

Q1
现在很多信息抽取任务可以用 LLM 完成，你会如何判断该用专用小模型，还是直接调用 LLM？两者怎么结合更划算？
▶
◈ 考察点 这道题考察候选人对信息抽取任务技术选型的判断能力。希望同学能从 成本、延迟、数据量、schema 稳定性等维度综合判断，而不是简单认为专用小模型或 LLM 一定更优。如果能进一步想到一些组合方案，比如用 LLM 蒸馏小模型，或采用"小模型 + LLM 复核"等方式，那就更好啦。
Q2
你的论文做了 AI 生成文本检测，也提到方法在水印扰动、跨模型、跨领域下容易失效。如果要把这套论文方法做成线上检测服务，工程落地会遇到什么问题？遇到没见过的新模型时，你会怎么处理？
▶
◈ 考察点 这道题考察候选人能否理解学术 benchmark 和真实开放世界之间的差距。学术数据集往往分布更干净，但线上场景会遇到跨模型、跨领域、水印扰动和未知模型等问题。因此，回答时建议不要只关注论文中的 SOTA 指标。如果能进一步结合线上落地场景，提出一些能真实落地的组合方案，比如"持续更新 + 概率输出 + 人工兜底"会更好。
Q3
作为 Agent 工程师，如果用户根据不同细分场景定义了几百个 Skill，导致 Skill 召回准确率下降，你怎么解决？
▶
◈ 考察点 这道题考察候选人是否真的思考过如何落地 Agent 类项目，并理解真实 Agent 使用中会遇到的问题。随着 Skill 数量增加，召回准确率下降是实际落地中常见的问题。如果同学能从业树优化和召回质量两个方向作答，例如分层召回、上下文感知、召回策略优化和 query 优化等，回答会更完整。

POSITION 04

AI 产品经理

字节跳动 · 2027 届校招
PRODUCT
PM
评估能力

▍招聘解读

AI 产品经理岗位的核心考察点是候选人对大模型的评估能力、产品化思维以及动手实践。期待同学既能用产品视角量化效果，又能用工程视角快速验证。

▍求职 Tips

✦ 评估与动手建议
  1. 准备一两个自己用 vibe coding 或 AI 工具搭出来的产品 demo，体现动手能力
  2. 面对复杂问题时能积极拆解、喜欢快速迭代的模型和工具，并能主动跟进并应用到业务中
  3. 展示对业务指标的量化思考（准确率、误判率、漏判率等）和迭代改进思路

▍面试真题测一测

Q1
如果你要把一个大模型能力引入业务场景（如内容治理），你会如何判断它是否好用？
▶
◈ 考察点 这道题考察候选人的 AI 产品评估能力。回答时建议大家除了"准确率高""用户满意"之外，也尽量指出治理场景的具体指标，比如准确率、误判率、漏判率、误判情况等，并说明这些指标和业务目标之间的关联。如果还有时间，还可以进一步分享一下效果不好的自己的例化思路（如提示词、Agent、工作流等），让面试官看到你的更多思考。
Q2
你自己用过什么 AI 工具或产品？过程中遇到过什么问题，怎么解决的？
▶
◈ 考察点 这道题考察候选人的动手能力和学习速度。如果面试前能展示一个自己用 vibe coding 做出来的产品，会是一个加分项。但建议进一步整理清楚：为什么做这个产品，解决了谁的问题，功能如何设计、遇到了哪些具体问题、怎么一步步改进，以及有没有真实用户使用或推广。
Q3
AI 技术日新月异，你如何学习和跟进最新技术？
▶
◈ 考察点 这道题考察候选人的韧性和适应能力。AI 技术日新月异，期待大家和我们一起可以持续学习。遇到复杂问题时能积极拆解、喜欢快速迭代的模型和工具能主动跟进并应用到业务中。

📌 总结

字节跳动 2027 校招四大重点 AI 岗位（大模型应用算法、AI 全栈、AI Agent、AI 产品经理）的核心考察点：

① 算法岗强调项目真实思考与训练技术深度（SFT/RL/Pre-Norm 等）；② 全栈岗看重端到端业务理解与 AI Coding 工具的实际使用；③ Agent 岗重点考察范式选择、技术选型与工程落地（幻觉、Skill 召回、模型选型）；④ PM 岗评估指标量化、动手能力与持续学习。
